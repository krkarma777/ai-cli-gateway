# v0.1 Release and SDK Onboarding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Publish AI CLI Gateway v0.1.0 as a verified five-platform GitHub Release and prove the existing non-streaming Responses API-compatible subset through the official OpenAI Python and JavaScript SDKs.

**Architecture:** A small internal Go package validates fixed release inputs, writes deterministic archives, finalizes a collection SPDX document, and emits checksums. A separate tag-only workflow calls the existing read-only CI, packages and attests assets without publication authority, verifies them in a read-only job, and grants contents write only to a final draft-first publisher. A Go SDK-contract runner launches the real gateway with a deterministic fake Codex CLI; a thin shell entrypoint and checked-in official SDK examples exercise the public HTTP boundary.

**Tech Stack:** Go 1.26.5 standard library, Go debug/buildinfo, the maintained stable `go.yaml.in/yaml/v3` v3.0.5 AST API used only by repository tests, GitHub Actions with every external action pinned to a verified full commit SHA, Syft CLI v1.50.0 and actionlint v1.7.12 built from exact Go module versions in private CI or external local temporary roots, actions/attest v4.2.2, OpenAI Python 2.53.0 on Python 3.12, OpenAI JavaScript 6.48.0 on Node 24.

## Global Constraints

- The controlling specification is docs/superpowers/specs/2026-08-04-v0.1-release-onboarding-design.md.
- Do not add an HTTP endpoint, streaming, tool calls, sessions, storage, a web UI, or a database.
- Keep the product description “Responses API-compatible subset”; never claim complete OpenAI API or SDK compatibility.
- Release tags must match exactly ^v(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$.
- Release targets are exactly linux/amd64, linux/arm64, darwin/amd64, darwin/arm64, and windows/amd64.
- Build with Go 1.26.5, CGO_ENABLED=0, -trimpath, -buildvcs=false, -mod=readonly, and linker flags -s -w.
- Every actionlint/Syft Go query, install, help, version, lint, or scan runs through validated absolute binaries under `env -i`, an explicit closed environment with private home/cache/tmp/config roots, and no PATH or ambient Go/Syft setting.
- A local external temp alias is physically canonicalized once and discarded; the retained canonical base, every ancestor, and the private leaf identity are validated before each isolated tool use and cleanup.
- Release outputs, SDK environments, node_modules, generated configs, logs, and binaries must remain outside the repository.
- Releasepack executes on Linux and macOS; Windows is an archive and compile target only. Its output root is an exact-mode-0700, effective-UID-owned, unshared transaction workspace beneath validated non-replaceable ancestor authority. Another process with the same OS identity must not mutate it while a releasepack subcommand runs, and such concurrent mutation is outside the v0.1 threat model.
- Never commit a provider credential, GitHub token, real authentication file, prompt, model output, or private filesystem path.
- Provider and gateway processes always receive argv arrays and stdin; never construct a shell command string from request data.
- SDK retries are disabled. The checked-in clients use a bounded 1..300-second timeout with a 300-second user default; the deterministic harness always sets it to exactly five seconds.
- The gateway binds only to 127.0.0.1 in all examples and tests.
- Keep Makefile’s exact eight public targets unchanged.
- Each implementation task must show a semantic RED before production code, pass its focused tests, receive specification and quality review, and end in its own commit.
